# pr_757: inkling: shared experts to the GPU, 1.75 to 2.46 tok/s on Apple Silicon

- **State:** OPEN (opened 2026-08-01 by rgbkrk)
- **Labels:** performance, metal

## Summary

Follow-up to #750 (inkling), but with two techniques worth knowing for GLM Metal work. Same validation discipline: greedy output token-identical through eos, tiny multimodal oracle exact at every step. Inkling-Small on Apple Silicon: **1.75 -> 2.46 tok/s decode, 10.3 -> 6.4 s prefill**.

- **Commit 1 — overlap shared experts with the last GPU round:** routed and shared experts are independent given the layer input; the last routed round submits with `moe_block_begin`/`_end` and the CPU computes shared experts while the GPU is in flight. `shared_done` flag guards double-compute on GPU fault. No new math, no new kernel. 1.75 -> 1.96 tok/s.
- **Commit 2 — shared experts on GPU as a bf16 block:** `moe_gemv` gains **fmt=5** (raw bf16 rows, no scales, dequant is a 16-bit shift into the upper half of an f32). Shared-expert weights move into one page-aligned slab per sparse layer; `Wt` handles repoint into the slab so the CPU fallback reads the same bytes. One fmt=5 block submitted per MoE layer before the routed rounds. Shared experts drop 8.0s -> 0.1s on the probe. 1.96 -> 2.46 tok/s.
- The fmt=5 branch is additive; glm/kimi call sites never pass fmt=5 (dead code for them). `INK_METAL_SHARED=0` opts out.

## Relevance

- **Goal a (fmt_2_m1u):** Perf technique reference — CPU/GPU overlap of shared experts and GPU-resident shared experts are candidate levers for beating 2.24 tok/s on M1 Ultra (GLM has 1 shared expert/layer currently on CPU).
- **Goal b (fmt_4_m1u):** **Code template** — the fmt=5 branch shows exactly how to add a new format branch to `moe_gemv` without touching existing paths, which is what Fix A (fmt=4 branch) needs.
