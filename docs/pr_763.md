# pr_763: metal: GPU attention for S>4 prefill (single command buffer)

- **URL:** https://github.com/JustVugg/colibri/pull/763
- **State:** OPEN (opened 2026-08-01 by RDouglasSharp)
- **Labels:** performance, metal, quality

## Summary

Lifts the `S<=4` cap on the Metal fused-attention path (`coli_metal_attn_decode`) so large-S **prefill** attention runs on the GPU in a single command buffer, cutting prefill attention time ~4x with output consistent with the CPU reference.

- **Off by default** — `COLI_METAL_PREFILL=1` opts in — because GPU prefill can pick a different token on near-tie logits (the #622 family), so a greedy stream is not guaranteed bit-identical to CPU
- `c/colibri.c`: fused-attention gate no longer hard-caps at S<=4; engageable for any S when Metal absorption is active; adds a cumulative timer to the `[prefill]` progress line
- `c/backend_metal.mm`: projections -> attention core -> output GEMV in one command buffer ordered by memory barriers (same structure as the token-exact S<=4 path); single `a_score` dispatch is `S*AHEADS*T` threads, guarded under ~2^30, CPU fallback for very large prompts
- `docs/metal.md` documents the flag. CPU and CUDA paths unchanged

## Relevance

- **Goal a (fmt_2_m1u):** Optional prefill speedup for the benchmark (~4x prefill attention) — with the documented near-tie caveat; keep it off for an exact-reproduction claim, or on for a max-speed claim.
- **Goal b (fmt_4_m1u):** Interacts with the same fused-attention gate that Fix C relaxes for fmt=4 — if both land, the fmt=4 gate change and the S>4 change must be reconciled in the same `if` conditions.
