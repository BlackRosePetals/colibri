# pr_386: Metal: platform-aware expert-cache defaults via honest storage probe (#379)

## Summary

Turns the #379/#387 findings into platform-aware defaults. On Apple Silicon with fast NVMe, stock defaults leave a large win on the table: 0.4 tok/s stock vs ~2.0 tuned (`MTP=0 CAP_RAISE=0 --ram 90 --cap 1`).

- Changes the defaults of exactly **two** knobs: `cap` and `CAP_RAISE`. MTP and RAM sizing remain manual — stock Metal runs land somewhere between 0.4 and 2.0 tok/s, not at 2.0
- Adds an **honest storage probe**: whether a volume is "fast" is measured, not assumed — buffered reads lie (page-cache hits read 23-97 GB/s; a real `F_NOCACHE` read measured 14 GB/s on the same file)
- Mechanism (from #379): Metal's per-buffer residency cost makes the engine's expert LRU anti-productive on fast NVMe; the OS page cache streams cold experts back cheaper than Metal can re-pin them
- Corroborated by #180 (M3 Ultra) and #107 (M4 Pro); explicitly invited by the maintainer (no Metal hardware in-repo)

## Relevance

- **Goal a (fmt_2_m1u):** The M1 Ultra benchmark runs on a tree that includes this PR — stock cache defaults are now platform-aware. When mirroring Configs A-E, know which knobs are already defaulted and which (`MTP`, `--ram`) remain manual.
- **Goal b (fmt_4_m1u):** Shared — same defaults context for fmt=4 runs.
